## The maintainer's direction on attachments (2026-11-24)

- The shared folder is configured in the helper; files are put there before a graph runs.
- A later iteration lets the helper download from an object store into the shared folder, for PDFs, images,
  spreadsheets and other inputs; until then an external script does the download.
- Asked whether the helper passes a reference to a local file to the model: no. The node passes a path to the helper,
  the helper reads the file and sends its bytes to the model in the request; the model reads nothing on the host and
  the path never reaches it. The build was unchanged by the answer, and the README now says who reads the file.
- Asked whether the file's content counts as input tokens: yes, in every call that names it, by what the model
  sees and not by the file's bytes - an image one token per 28 by 28 pixel patch up to its tier's cap (1,568 or
  4,784), a PDF page its text plus an image of at most 1,568. The README gained "What it costs".
- Asked whether the audit should keep the file: no, a reference with the size and the SHA-256, as built. The hash
  tells whether a file is still the one the model saw and cannot bring it back, so an installation that must
  reconstruct an exchange keeps its files unchanged for the audit's retention; with an object store, versioned
  objects and the version id in the reference. The README says so. No archive copy inside the helper.
- Checked on the provider's page, for the later iteration: plain text such as `.csv` can go in a document block;
  a binary format such as `.xlsx` or `.docx` cannot and is converted to text or PDF first.

## What was done

**RFC-0015, the audit of a single call** (`extensions/llm-helper/llm_helper.py`):

- `llm.transcript.audit.single` (off by default). With it and an audit store, a call without `tools` on `llm.chat` or
  `llm.stream` is recorded once the model has answered and before the reply is judged: `_single_record` builds a
  closed one-turn version 2 record (the messages as sent, the assistant's blocks as returned, the system prompt, no
  tools, the turn's facts, the model that answered), `_save_single` saves it under a new reference with the audit's
  grace and sends `{conversation, check: true}`. `transcript.audit`, `_audit_apply` and the sweep are untouched.
- The reply does not wait: the save is a task held in `_single_saves`; `audit_single_idle` drains it at shutdown.
  A store that is missing or fails is logged by type and that call is not audited. `audit_boot` stops the
  application by name when the switch is on and no working store is configured.

**RFC-0016, attachments** (the same file):

- `attachments` on `llm.chat`: `_attachments`, `_attachment` and `_pages` check the shape in `prepare()` after the
  schema; the field is a 400 on `llm.stream` and on a loop turn.
- `attach()` runs inside the call's deadline (`_answer` under the one `asyncio.wait_for`) and reads the files in a
  worker thread: `attachments_root` (one root, resolved once; unset is a 503), `_attachment_file` (a relative path,
  the resolved path inside the root, no hidden entry, a regular file), `_media_type` (the first bytes), `_pdf` (pypdf:
  encrypted or unreadable refused, the pages cut in the order named), `_load_attachments` (the byte bound from the
  files' sizes before a read, an image's limit by backend, the blocks and the references).
- `Backend.image_max_encoded`: 10 x 1,048,576 on the Claude API, 5 x 1,048,576 on Bedrock.
- With the audit of a single call, the record's last turn holds `{type: attachment, path, pages, media_type, bytes,
  sha256}` in place of each file, the hash taken from the source file as it was read.
- `attachments_boot` stops the application when the configured root is not a folder.

**Tests and shared files:**

- `tests/vectors/llm-audit-vectors.json` (new, 25 cases) and six tests in `tests/test_transcript_audit.py`.
- `tests/vectors/llm-attachments-vectors.json` (new, 48 cases), eight fixture files in `tests/fixtures/attachments`

## Decisions

- **The maintainer's:** build both; the shared folder and the object store as above.
- **Made here, as defaults without a ruling - each is an open question of its RFC entry:**
  - RFC-0015: the switch off by default; `llm.stream` recorded under the same switch; `model` the model that
    answered; a stop reason outside the loop's table recorded as `done`; the reply not waiting for the save; one
    event, the check, since a one-turn record's first write is its last; the switch without a working store stopping
    the application at start.
  - RFC-0016: one root; the byte bound on source files; no page limit of the helper's own; not on `llm.stream`; the
    `documents` extra; a missing root as a 503 and a root that is not a folder as a stop at start; hidden entries
    refused with no switch; a whole PDF checked only when pypdf is installed; a `null` field treated as absent.
