## What happened

- **Design.** `mercury_composable.otel` (config / span / otlp / export / activation). `bus.py`'s `_emit_trace` now
  returns the dataset and `EventBus._forward` publishes it to `distributed.trace.forwarder` when a function is
  registered there — WITHOUT a trace, so the forwarder's own execution emits no dataset (the engines' zero-tracing
  forwarder, with no new flag). `Platform.run()` calls `otel.activate(config, registry)` before announcing the
  routes and closes the exporter's aiohttp session on the app's cleanup. The built-in forwarder registers private,
  two workers; an application's own function on the route wins. Keys, defaults, span mapping (exact W3C ids; a
  non-W3C dataset is skipped, never forged), retry (5 attempts, 1 s × 1.5ⁿ on transport failures and
  408/429/502/503/504), diagnostics (401/403/404/413/429 hints, body bounded to 256 chars, headers never rendered)
  and the per-export credential re-read all mirror the Rust port. Two deliberate deltas from the engines:
  `otel.exporter.otlp.connect.timeout` IS honoured (aiohttp connect timeout), and the instrumentation scope is
  `mercury-composable-python` so a backend shows which runtime produced a span.
- **Tests** (`tests/test_otel_forwarder.py`, 17): headers parsing (both forms, first separator), the mapping (ids,
  metrics, error status, non-W3C skipped), ISO-8601 nanos, the wire format round-tripped through a decoding
  collector (the Rust tests' MockCollector twin), partial-success reader, diagnostics text, endpoint validation,
  delivery + credential arrival, retry to success, final rejection not retried, refused connection retried then
  reported, credential re-read per export, the switch, an application's own forwarder winning, a bad endpoint
  failing activation, and the host hook end to end (a traced drop-n-forget execution reaches the collector as one
  span with the caller's trace id — and exactly one, proving the forwarder's own run is untraced).
- **Gates:** ruff (isort) clean, basedpyright 0/0, pytest 114 passed (17 new), mkdocs strict OK.
