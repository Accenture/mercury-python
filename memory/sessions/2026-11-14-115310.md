**Title:** Trace records mirror the engines' callee and caller - a span lineage continuous from an engine into the pack

## Context

Follows 2026-11-14-104712 (the `@preload` shape of the MCP binding, #52). Eric asked how the alias shape appears in a
trace, then for a live end-to-end drive from the Java engine to both language packs with the telemetry recorded, and set
the criterion: for OpenTelemetry to be certified, the span lineage ought to be continuous end to end.

## What the drive found (the baseline, negative control first)

The Playground's `diagram-assistant` graph on Claude Haiku 4.5, the engine calling this pack's LLM helper (`llm.chat`,
port 8086) and MCP binding (`diagram.render.mcp`, port 8088, the public Mermaid Chart server). Every record the engine
logged chained to a parent that exists, but the pack legs left no record anywhere: 11 engine records, none from the
pack. Two rules met: the calling engine's HTTP client leg `async.http.request` is in `skip.rpc.tracing` by default, so
the caller records nothing for a wire RPC; and this host suppressed the worker-side record of every RPC-served execution
("engine parity") without the callee-side records a Java engine leaves for the same call - the `http.request` edge
(`POST /api/event`), `event.api.service` and the function's round-trip record from the local inbox. The forwarder drops a
record without a valid span id, so even an engine inbox record for a pack route would not have reached a backend: the
reply carried no span.

## The design Eric chose

Three shapes were offered: mirror the Java callee exactly, one record per wire RPC, or keep the rule and document it.
Eric chose the first.

## What changed (branch `feat/trace-records-engine-parity`)

- `src/mercury_composable/bus.py`: the reply carries the responder's span (`WorkerHandler` parity); `round_trip_record`
  builds the engines' `InboxBase` record; `EventBus.emit` logs a dataset and forwards it.
- `src/mercury_composable/client.py`: a traced local RPC (plain or interceptor) is recorded by the caller's side with the
  responder's span, the caller's span as parent, the responder's `exec_time` and the measured `round_trip`.
- `src/mercury_composable/server.py`: `_Edge` records a traced call at `/api/event` as the Java callee does -
  `http.request` (the edge's round trip, parent the caller's span: the envelope's, else the `traceparent` header's),
  `event.api.service` (parent the edge), the function's round-trip record for an RPC (parent the service); the relayed
  envelope carries the service's span, so a drop-n-forget or streaming function parents onto it; a refusal (403, 404), a
  timeout (408) and an in-band stream failure leave the edge record with that status; an untraced call records nothing.
- `tests/test_event_stream.py`: the two tests that pinned "RPC legs emit no dataset" now pin the engines' rule, and a
  new test pins the wire RPC's three records, the responder's span on the reply, the refusal's edge record and the silence
  of an untraced call.
- `docs/guides/config-logging-actuators.md` states who emits which record; CHANGELOG Unreleased Changed 4; the MCP
  binding's README gains a Tracing paragraph (the alias never appears; the route is the identity).
