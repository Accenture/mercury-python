## What We Did

- **The rule (Eric's):** the configuration is resolved relative to the application file - the file `mercury-serve` is given, or
  the script Python ran (`python app.py`, `__main__.__file__`) - and the working directory is never searched: the engines'
  classpath convention, the configuration travels with the application and does not depend on the launch directory. Before, the
  CLI searched the working directory first and the app's folder only as a fallback, and the lazy singleton (the direct-run path)
  probed the working directory alone - which is why `python examples/llm-helper/llm_helper.py` from the repository root started
  with no configuration during the Bedrock drive (the default name and port, no health dependency).
- **Code (`6d337e2` on `fix/resources-next-to-the-application-file`, PR #45 MERGED 2026-10-14, merge `a3c5a26`):** `AppConfig(path, argv, app_dir)` resolves
  `DEFAULT_CANDIDATES` under `app_dir`, defaulting to `main_script_dir()`; `load_config(path, app_dir)`; the CLI checks the app
  file first, then `load_config(config_arg, app_dir=dirname(app_path))` - no probing loop; `resources_dir` (beside an explicit
  file, else `<app_dir>/resources`, None with neither) is where `log_context` looks for `app-log-context.yaml` (it used to fall
  back to the working directory's `resources/`); `source` is the absolute path found; `Platform.run` logs
  `Configuration: <source>`. An explicit `--config` file that does not exist still raises `FileNotFoundError`.

## Decisions

- Script-relative only, no working-directory fallback (Eric: "it should not scan any directory"): a lookup that starts in cwd
  makes the loaded configuration depend on the launch directory and lets a stray `resources/` shadow the app's own; the rare
  layout that relied on it passes `--config` or moves the folder (the CHANGELOG's upgrade note).
- An interactive session (no `__main__.__file__`) loads nothing rather than probing cwd; `load_config(path)` is the explicit way.
- `source` becomes an absolute path; `resources_dir` is the one folder companion files share with the configuration file.
