## What We Did

- **Record version 2.** `Transcript` gains `retention`, `correlation_id`, `graph_id`, `node`, `system`, `tools` and
  `turns` (one entry of facts per turn: trace id and path, correlation id, the model call's UTC bounds as ISO-8601
  milliseconds, status, stop reason, request id, usage, and `messages: [first request message, response]`); `to_json`
  writes `v: 2`, `from_json` reads version 1 with the defaults. `_loop_turn` takes the headers now: the first turn
  records the correlation id (the trace context's `my_correlation_id`, else the header view), `x-graph-id` and
  `x-node` (null when a caller sends none), the system prompt and the catalog once; every turn appends its facts inside
  the compare-and-set (`_first_record`, `_turn_facts`, `_record_ttl`, `_notify_audit` keep the function under the
  complexity threshold). The 66 shared loop vectors pass unchanged: the harness reads turn, closed, pending, ttl and
  the message count, none of which moved.
- **The store protocol's audit half.** `audited`, `mark_audited`, `release`, `unaudited` and `sweep_lock` on both working
  stores. Memory: a fourth tuple element the compare-and-set preserves. Redis: a third hash field `audited` set by a
  Lua that writes only when the key exists (a bare HSET would resurrect a released record with no TTL), `DEL` or
  `EXPIRE` on release, `SCAN transcript:*` reading two fields per record and skipping anything that is not a 32-hex
  conversation (the sweep's lock `transcript:audit:sweep` lives under the prefix so one ACL covers it), and
  `SET NX PX` for one sweep per interval across the replicas.
- **The function `transcript.audit`** (`_audit_apply`): load the record, read the turn numbers the audit store holds,
  write every missing turn that has facts in one transaction with the conversation row, log turns without facts as
  unaudited (a version 1 record), then the mark and the release: a check on a closed record releases it to its
  `retention` and marks it afterwards; a write of a closing turn leaves both to the check behind it; an open record is
  marked and never released. A failure is logged by type and SQLSTATE (`_audit_failure`: the first line only for a
  connection-class or configuration error, because a constraint violation's DETAIL quotes the failing row). `llm.chat`
  sends the two events through a module-level `PostOffice()` with no endpoint (`_audit_send`: a 404 or an exception is a
  warning, never a refusal). The sweep (`audit_sweep`, `_sweep_forever`) and the boot (`audit_boot`: register the route
  with one instance when configured, open the store - a missing driver is a SystemExit by name, a database that does
  not answer a warning - and start the sweep task; `audit_shutdown`) hang on `platform.on_startup` / `on_cleanup`.
- **PostgreSQL.** `PostgresAuditStore` on psycopg 3's `AsyncConnectionPool` (`postgres` extra, `psycopg[binary,pool]`),
  four statements as module constants: the upsert of the conversation row (`ON CONFLICT (conversation) DO UPDATE` of

## Decisions

- Build precisions on the settled spec, recorded for the Node twin: `request` is the JSON array of the messages a
  turn sent (one normally; a first turn with a history sends them all) and `response` the array of assistant blocks -
  constant shapes for SQL; a closed record's audited mark is set by its check after the release, so `audited < turn`
  means "the check has not completed" and the sweep re-sends the check of a closed record whose check failed; any
  closed record (a `max_tokens` cap included) waits with the grace when the audit is on and the check releases it to
  `retention`; a version 1 record's turns without facts are logged, then the record is marked and released (nothing more
  can be done); the dev credential reaches the helper through the shipped yml's environment references, never a `-D`.
