## What We Did

- **`extensions/ask-person/ask_person.py`:** `person.ask`, the composable function a graph's hold path calls before it
  suspends. The message is validated in a fixed order (kind; the four texts; node; requested_at; for a wait the turn, the
  calls with their ids and the ttl; an advice refuses calls and ttl) and becomes one event: the message plus, for a wait,
  the signed stateless ticket (`v1.<payload>.<mac>` - canonical JSON of `{g, c, t, k, e}`, HMAC-SHA256, base64url
  without padding; the previous key verifies after a rotation; the base64url alphabet is checked before any decode), the
  resume link and `expires_at` = `requested_at` + `ttl`. The event goes to every route in `ask.channels` in parallel and
  best effort - a local route or a peer over the endpoint listed for it - and `delivered` says which took it; a failure
  is logged by type, never by content, and never fails the hold. `advice` (R8) travels with no ticket and no link.
- **The reply page and endpoint**, mounted on the host: `GET /ask/{ticket}` verifies the ticket, identifies the person,
  asks the engine for the current wait by the reference graph's re-advice (`{turn}` on the allowlisted entry with the
  correlation id) and renders the form - approve or refuse with a note, an answer with the options offered, a call that
  runs on resume - and never resumes; `POST /ask/reply` verifies, identifies, validates the decisions, prefixes
  `[who at time]` to each tool call's note, sends `{turn, decisions}` and passes the engine's status and body through
  (a silent engine or one outside the contract is a 502). Identity: `none` (development), `proxy` (the gateway's header),
  `oauth2` (PyJWT against the issuer's JWKS, discovered or given; the new `ask` extra), and a channel app's bearer with
  `decided_by` in every mode (R7 applied to the page by extension, Q6).
- **The host hook:** `EventApiServer.create_app(routes)` and `Platform.add_routes(mount)` register an extension's routes
  after the host's paths and before the catch-all (Q4 as agreed).
- **The shared vectors** `tests/vectors/ask-person-vectors.json` (72 cases: ticket, verify, message, re-advice, reply,
  outcome), generated from the module and cross-checked: the first ticket's MAC reproduced with `openssl dgst -hmac`
  byte for byte, so the Node twin can implement the ticket from the file alone. `tests/test_ask_person.py` (100 tests)
  runs them and drives the function on the bus (channels that take, refuse and miss), the page and the endpoint against a
  fake engine, the three auth modes with a signed RS256 token, the hook's ordering, the boot's refusals by name, health
  and `inspect`.
- README, `resources/application.yml`, CHANGELOG Unreleased/Added 5, the root README's Scope paragraph, the `ask` extra
  and PyJWT in the dev extras.
- **Decisions taken in the build, for Eric's eye:** the allowlist and the channel endpoints are YAML lists of maps
