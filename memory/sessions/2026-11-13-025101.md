## Context

for Python, whose releases were cut as 13 `release/*` branches; tags began at `v4.12.0`. Eric asked for the approach
taken in mercury-composable (2026-11-12) and in the Rust port (2026-11-13) to be applied here: tag each historical
release, publish it as a GitHub release never marked latest, delete the branches, and change the README's "remains in
git history" to "remains in tagged releases".

  peeled to their planned commits.
- **Releases.** Each note is the version's CHANGELOG section read at its tag, after one line saying it was published
