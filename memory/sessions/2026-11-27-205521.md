## Decisions

Taken inside the fix, named in the pull request for the reviewer, accepted by the merge:

- The label's name is fixed, `_Ingested`, not a configuration key; the underscore keeps it out of the callers'
  names, since a caller's label starts with a letter.
- A uniqueness constraint, not a plain index: it makes a concurrent `MERGE` of one key safe and the key unique; a
  graph that already holds a key on several nodes is refused with a 409 until repaired.
- The tool prepares the graph itself at the first ingest of a process, labelling before constraining: a merge
  through the label would not find an unlabelled node and would write it a second time (verified on the database).
- `graph.schema` leaves the label out; a query result shows it.
- Another dialect is labelled and matched, never refused; its index is the installation's.
