## Defaults set without a ruling (for the spec's build notes, section 14)

1. A relationship whose endpoint does not exist fails the whole ingest with a 400 naming the key - checked inside the
   transaction after the node merges, so nothing is half-written; never a silent skip.
2. Rows are capped by configuration only (`tools.graph.max.rows`, 200, the tool's cap 2000); the model narrows with
   `WHERE` and `LIMIT`.
3. An ingest call carries at most `tools.graph.ingest.max.nodes` nodes and four times as many relationships; a key is at
   most 512 characters; property names are identifiers; `key` and `source` are the tool's; a null value is dropped.
4. `graph.write` returns `columns`, `rows` and `truncated` beside `counters`, so a `RETURN` after a write is kept.
5. A label the property procedure lists with no instance, or a type with no property, still appears with count 0.
6. The rendering: a node `{id, labels (sorted), properties}`, a relationship `{id, type, start, end, properties}`, a path
   the alternating list, temporal values `iso_format`, a point `{srid, coordinates}`, bytes base64.
7. A database that does not answer at boot is logged and its tools answer 503 until it does (the audit store's
   precedent, [[transcript-audit-store-python]]); a URI that is not Bolt, or set without the driver, stops the boot.
8. `file.extract` returns `type` (`pdf`, `docx`, `html`, `text`) and the document's page count; a Word document is one
   page; `tools.file.extract.max.chars` (60 000) is the cap key the paper did not name.
