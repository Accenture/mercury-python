## What We Did

- **`extensions/agent-question/agent_question.py`**, a standalone application on the package and the first channel
  of RFC-0014's Part II. `agent.question.inbox` takes the message event the main flow sends like any route: a wait is
  upserted on `(graph_id, correlation_id, turn)` - a re-advice for the same turn updates the card - and an advice is
  appended; one instance orders the writes of a process, and the row is committed before any push. Two inboxes behind
  one protocol: `MemoryInbox`, the reference semantics (ids and a change sequence assigned here), and `PostgresInbox`
  on psycopg 3 with the audit store's connection keys, server-side statement timeout and failure logging by type and
  SQLSTATE; the schema's partial unique index makes waits upsert and advices append, and `question_inbox_seq` is the
  cursor a replay reads from.
- **The person's side** under the host through `Platform.add_routes`: the page (vanilla HTML, cards grouped by
  transaction, a name field in development), the replay `GET /questions?since=<seq>` with the cursor to continue
  from, the stream `GET /questions/events` (rows since `Last-Event-ID`, then every change, keep-alive comments from
  the host's `event.stream.keep.alive`), the automated click `POST /questions/{id}/decide` - the link's own base plus
  `/ask/reply`, `{ticket, decisions, decided_by}` under the app's bearer, the outcome recorded and broadcast, the
  state by `state_after` (accepted → answered, nothing waiting → expired, refused or unreachable → open) - and
  `POST /questions/{id}/seen` for an advice. A sweeper and every replay expire open waits past their expiry.
  Identity as the main flow's: `none`, `proxy`, `oauth2`.
- **Defaults set without a ruling, for Eric's eye:** the inbox defaults to memory with a boot warning, PostgreSQL for a
  deployment; the connection keys follow the audit store (`question.inbox.postgres.*`) rather than one URL; the app
  keeps no retention key - `schema/purge.sql` carries the installation's interval; a re-advice updates the row in place,
  so the spec's `superseded` state is not needed and the states are open, answered, expired and seen; a decision the
  loop refused leaves the row open with the outcome shown, since the graph re-notifies with the reason anyway; a bare
  number in `timeout.ms` is milliseconds (the key's name), in the durations seconds.
- Shared vectors `tests/vectors/agent-question-vectors.json` (30 cases: the row a message becomes, the state an
